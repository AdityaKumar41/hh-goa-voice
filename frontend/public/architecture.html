02 / THE SEAM

ResearchHarness owns the sequence.

Guard → retrieve → fit context → generate → validate → trace. This keeps fast and normal answers under one policy boundary.

03 / MEMORY

Operational memory is not user memory.

PostgreSQL stores query traces and index metadata. v1 intentionally has no personal conversational memory or profile store.

04 / TOOLS

External research stays read-only.

Jina Reader and Firecrawl are optional tools behind the bounded workflow. They do not write to the platform or silently expand its knowledge base.

05 / LLM OPS

Every release has an evidence loop.

Index versions, manifests, latency checks, refusal checks, grounding validation, and privacy-safe traces support safe promotion.

Architecture truth

The production system is deliberately stateless at the conversation layer: each request is grounded against the shared, versioned corpus. Qdrant is the retrieval memory; PostgreSQL is the operational record; traces and evaluations are the LLMOps feedback loop. That boundary is visible here so “memory” is never implied where it is not implemented.
